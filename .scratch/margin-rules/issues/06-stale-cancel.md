# 06: Stale cancel: resting plain orders are cancelled after 60 s without a report

**What to build:** When the link is up and no margin report has been accepted for more than 60 seconds, the tick requests one rule cancel, actor `Rule(MarginStale)`, for every resting plain order. Reduce-only orders stay. Nothing latches: the next accepted report restores normal acceptance. A node that never received a report measures the age from the moment its link session came up. Scenario row: S23. Claim: V-MARGIN-7.

Without this, orders resting from before the policy would never be cancelled when no report follows; reading the missing time as zero would cancel them on the next tick.   - Still not guaranteed: the position stays, the OMS closes nothing. Reduce-only orders stay. Nothing is cancelled while the link is down; when the link returns the new session gets its own 60 s, so orders can rest without a report for the outage plus 60 s. A cancel can lose the race to a fill; the fill is then booked. An order whose cancel is exhausted is not asked for again (the operator sees `CancelStuck`). Behaviour under random interleavings is not tested here (simulation, ticket 10), nor through the node process (no seam C test in this ticket). A report that is recorded but old on arrival moves the baseline to its query time, so it does not by itself stop a stale episode.
