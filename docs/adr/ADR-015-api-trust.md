# ADR-015 로컬 API와 신뢰 경계

상태: 채택.

## 1. 문제와 발생 가능한 실패

- 누구나 접속해 주문을 낼 수 있다.
- 한 전략이 다른 전략의 주문을 취소하거나 본다.
- 조회 화면에서 실수로 거래를 멈추거나 재개한다.
- 비정상적인 입력(거대한 줄, 잘못된 숫자)이 프로세스를 멈춘다.
- 운영 명령이 흔적 없이 실행된다.

## 2. 일반적으로 만족해야 하는 성질

접근 주체가 식별된다. 주체별로 할 수 있는 일이 정해져 있다. 모든 입력은 신뢰 경계에서 검증된다.
상태를 바꾸는 운영 명령은 기록된다. 조회 경로와 변경 경로가 분리된다.

## 3. 제약

전략은 같은 호스트의 별도 프로세스다. 운영자는 한 명이고 그 호스트에 로그인한다. 원격 접속은 요구되지 않는다.

## 4. 필수 조건과 선택 조건

필수: 호스트 밖에서 접근 불가. 운영 명령은 별도 경로. 입력 크기 상한과 형식 검증. 운영 명령의 감사 기록.
선택: 전략 간 격리를 OS 사용자 수준으로.

## 5. 대안

| 대안 | 설명 |
|---|---|
| A. loopback TCP + 토큰 | 127.0.0.1에 포트를 열고 요청에 토큰을 싣는다 |
| B. Unix 소켓 + 파일 권한 + 상대 사용자 확인 (가장 단순) | 소켓 파일의 권한과 `SO_PEERCRED`의 uid |
| C. HTTP/gRPC + TLS + 인증 | 원격 접속까지 고려 |

## 6. 비교

| 기준 | A | B | C |
|---|---|---|---|
| 호스트 밖 노출 | 바인딩 실수 시 노출 | 불가능(파일) | 의도적으로 노출 |
| 주체 식별 | 토큰(비밀 관리 필요) | 커널이 알려 주는 uid | 인증서·토큰 |
| 같은 사용자 안의 프로세스 구별 | 토큰으로 가능 | 불가 | 가능 |
| 비밀정보 | 토큰 | 없음 | 키·인증서 |
| 구현·검증 비용 | 중간 | 낮음 | 높음. OWASP ASVS의 인증·세션·통신 장이 모두 적용된다 |

이 표의 값은 모두 정성 판단이다. 측정값은 없다.

## 7. 선택과 이유

B. `crates/oms-node/src/server.rs`.

| 소켓 | 권한 | 접속 허용 | 허용 동작 |
|---|---|---|---|
| `oms.sock`(거래) | 0600. `allowed_uids`가 있으면 0666 + uid 확인 | 프로세스 소유자, 설정에 적은 uid | `hello`에서 밝힌 전략으로 주문·취소·조회·구독 |
| `admin.sock`(운영) | 0600 | 프로세스 소유자만 | 위 + 중지·재개·불일치 확인·주문 종결·전체 취소·포지션 조정·스냅샷 |
| HTTP 대시보드 | loopback만 바인딩(설정 검증이 강제) | 호스트의 누구나 | 읽기 전용. 상태를 바꾸는 경로가 없다 |

- 전략 연결은 자기 전략의 주문만 보고 취소한다. 다른 전략의 주문 조회는 "없음", 취소는 `not_owner`다.
- 연결 수의 상한은 두 소켓이 따로 가진다(거래 64, 운영 8). 거래 소켓의 연결이 아무리 많아도 운영자의 중지와 취소는 막히지 않는다.
  `hello`를 하지 않는 연결은 10초 뒤 닫힌다. 한 연결의 구독은 하나다. 간격 검토 전에는 상한이 하나였고, 구독하고 떠난 연결이 자리를 돌려주지 않아 운영 소켓까지 막힐 수 있었다.
- 운영 명령은 `Operator` 입력으로 코어를 거쳐 사유(`note`)와 함께 저널에 기록된다. 저널이 감사 기록이다.
- 장애 주입 기능은 OMS에 없다. 가상 거래소 프로세스의 제어 명령으로만 가능하며 그 소켓은 OMS와 별개다.
- 입력 검증: 한 줄 64 KiB 상한, JSON 구조 검증, 식별자 문자 집합과 길이, 수치는 십진 문자열만(JSON 숫자 거부), 음수·과도한 소수 거부.
  이후 코어가 업무 규칙을 검증한다. 클라이언트 입력은 코드·경로·형식 문자열로 해석되지 않는다.
- 자원 상한은 [ADR-010](ADR-010-overload-storage.md)에 있다.

### OWASP ASVS 5.0과의 관계

ASVS는 웹 애플리케이션 보안 검증 요구다. 여기서는 점검 축으로만 쓰며 준수를 주장하지 않는다.
조사에서 현재 설계와 충돌할 수 있다고 지적된 두 요구에 대한 판단:

| 요구 | 내용 | 판단 |
|---|---|---|
| v5.0.0-8.4.2 | 네트워크 위치만으로 권한을 부여하지 않는다 | HTTP 대시보드는 loopback이라는 위치만으로 읽기를 허용한다. 읽기 전용이고 비밀정보가 없어 수용한다. 원격 열람이 필요해지면 재검토한다 |
| v5.0.0-7.2.2 | 정적 API 키를 세션 토큰으로 쓰지 않는다 | 토큰을 쓰지 않으므로 해당 없음. 식별은 커널이 제공하는 uid다 |

## 8. 포기한 장점, 남은 위험, 가정

- 같은 OS 사용자로 실행되는 프로세스는 어떤 전략으로든 접속할 수 있고 운영 소켓도 열 수 있다. 전략 간 격리가 필요하면 전략마다 OS 사용자를 나누고 `allowed_uids`를 쓴다.
  그 경우에도 "어느 uid가 어느 전략인가"는 검사하지 않는다(uid 허용 여부만 본다). 남은 공백이다.
- 대시보드는 호스트의 모든 로컬 사용자에게 주문과 포지션을 보여 준다.
- 전송 구간 암호화가 없다. 호스트 내부 통신이다.
- 호스트 자체가 침해되면 보호가 없다.

## 9. 근거

- `a_strategy_sees_and_cancels_only_its_own_orders`, `external_activity_is_detected_and_needs_an_operator`(거래 소켓에서 운영 명령 거부),
  `wire_examples`(JSON 숫자 거부), 식별자·수치 파싱 시험.
- 시험하지 않은 것: 다른 uid로의 접속(시험 환경이 단일 사용자). 거대한 줄과 느린 클라이언트에 대한 프로세스 수준 시험.

## 10. 재검토 조건

전략이나 운영자가 다른 호스트에서 접속해야 할 때(C로 전환, ASVS의 인증·통신 장 적용). 대시보드를 원격으로 볼 때.
