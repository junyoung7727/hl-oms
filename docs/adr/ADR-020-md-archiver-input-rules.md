# ADR-020 아카이버가 계약에 없는 다섯 곳을 정하는 방법

상태: 채택, 구현됨(2026-11-19, U7 `.scratch/md-archiver/`). 계약(quant-data-platform `docs/crypto/lake-contract.md`)은 바꾸지 않았다. 아래 1번과 5번은 계약에 넣자고 qdp에 제안할 질문이다.

## 1. 문제

`md-archiver`는 봉인된 L0에서 L1을 만든다(계약 §3). 계약과 골든 픽스처가 정하지 않은 곳이 다섯 있다. 정하지 않으면 같은 L0에서 실행 시점에 따라 다른 L1이 나오거나(결정성 위반), 보존 정리 뒤 같은 날짜를 끝없이 다시 만든다.

## 2. 결정

1. **어느 종목정보 응답을 쓰나.** 레코드의 종목 S는, 그 레코드가 든 파일 날짜 X의 X−7…X 종목정보 파일 중 `recv_ns`가 레코드 이하인 **S를 담은** 가장 늦은 응답의 행을 쓴다. 이하인 응답이 없으면 그 창에서 S를 담은 가장 이른 응답을 쓴다(수집기는 구독 전에 종목정보를 받으므로, 몇 ms 늦은 응답만 이 경우다). 창에 없으면 `parse_error`다. 창은 X 뒤를 보지 않는다. 그래서 결과가 실행 시점에 기대지 않는다. 쪽 나눔(선형 1,000개씩)이 있어서 "S를 담은" 응답만 센다.
2. **전날 상태.** D를 만들 때 D−1을 처음부터 다시 재생해 00:00 상태를 얻는다(행은 쓰지 않음). D−1의 레코드는 D−1의 창(1번)을 쓴다. D−1이 L0는 있는데 일별 봉인 전이면 D를 만들지 않는다. D−1에 L0가 아예 없으면 이어받는 상태 없이 만든다. 한계: D−1에 스냅샷이 하나도 없이 D−2부터 살아 있던 호가 상태는 이어받지 못한다(자정 전환이 하루 실패해야 생김).
3. **"다 만든 날짜" 표시.** `gap` 일 파일이 있으면 그 날짜는 만들어졌다. 그래서 gap 파일은 행이 0개여도 늘 쓰고, 맨 마지막에 이름을 바꾼다(지우기 → 다른 파일 → gap 순서, 단계마다 fsync).
4. **보존 정리.** `--retain-l1-days N`은 `book_msg`·`trade`·`ticker`만 지우고 `gap`·`instrument` 일 파일은 남긴다. 둘 다 작고, gap 파일이 남아야 다음 실행이 그 날짜를 다시 만들지 않는다. 되살리려면 `--rebuild`.
5. **`first_update_id`·`last_update_id` 메타데이터.** 계약은 파일마다 값 하나를 요구하지만 파일에는 종목이 여럿이다. 파일 정렬 순서에서 `update_id`가 있는 첫·마지막 스냅샷/변경분 행의 값을 쓴다(없으면 빈 문자열). 종목 하나만 볼 때만 뜻이 있다.

검토(명세 R1–R11)에서 정한 해석도 여기에 둔다.

- **겹침(R1·R2).** A가 끝날 때(마지막 레코드, 어느 토픽이든) 그 토픽을 나르는 다른 연결이 살아 있으면(`first ≤ A.last ≤ last`) 겹친다. 핸드오버는 c가 f보다 늦게 시작해 f가 살아 있는 동안 시작했고(`f.first < c.first ≤ f.last`) 그 스냅샷이 c의 첫 스냅샷일 때다. 그래서 자정 연결의 스냅샷이 옛 연결의 마지막 레코드보다 늦게 와도 재연결이 아니라 핸드오버다. 따라가던 연결이 끝난 뒤 호가 상태를 이어 주는 것은 "대기 중 핸드오버"뿐이다: 그때 살아 있으면서 그 토픽을 아직 하나도 보내지 않은 연결. 이미 그 토픽을 보내던 연결(그 변경분은 이 책에 반영되지 않음)은 상태를 이어 주지 않고, 따라가던 연결이 끝난 뒤 다른 연결에서 스냅샷 전에 온 메시지는 상태를 끝낸다(최종 검토 F1). 그래서 체크포인트가 빠진 행을 둔 채 멈춰 있지 않다.
- **호가 상태 끝(R3).** 어느 연결의 `seq_gap`이든, 그 종목의 `parse_error`든 호가 상태를 끝낸다(계약 §3.2, §7).
- **재스냅샷(R8).** 그 연결의 순번 추적이 살아 있을 때만 `resnapshot`이다. Bybit는 공백 뒤 같은 연결에 다시 구독해 스냅샷을 보내는데, 이것은 `resnapshot`이 아니다.
- **지수 변경(R9).** 따라가는 호가의 종목정보 지수가 바뀌면 호가 상태를 끝낸다. 지수가 다른 호가 단계가 한 책에 섞이지 않는다.

## 3. 대안

| 대안 | 버린 이유 |
|---|---|
| D+1의 종목정보도 본다 | D를 만들 때 D+1이 봉인됐는지에 따라 결과가 달라진다 |
| 전날 상태를 L1의 마지막 체크포인트에서 읽는다 | 체크포인트에는 연결 수명(어느 연결이 언제 끝났나)이 없어서 자정 직후의 재연결·핸드오버를 정할 수 없다 |
| 별도 "완료" 표시 파일 | 계약이 `_`로 시작하는 이름을 예약해 둔다. 새 이름은 계약 변경이다 |
| 보존 정리 때 gap도 지운다 | 다음 실행이 그 날짜를 다시 만들고, 다시 지운다 |

## 4. 결과

- 한 날짜를 만들 때 L0를 D−1·D 각각 두 번(연결 수명, 재생) 읽는다. 큰 날짜의 시간은 아직 재지 않았다.
- `by_connection` 배치는 읽지 않는다(실행 거절, 종료 2).
