# ADR-009 수치 표현: 1e-8 고정소수점 정수와 십진 문자열

상태: 채택.

## 1. 문제와 발생 가능한 실패

- 부동소수점으로 가격·수량을 다루면 `0.1 + 0.2`가 tick 검사를 통과하지 못하거나, 누적 오차로 포지션이 어긋난다.
- 곱셈이 넘쳐 한도 검사가 음수와 비교된다.
- JSON 숫자를 읽는 도구(브라우저, jq)가 2^53을 넘는 정수를 조용히 반올림한다.
- 반올림 방향이 일정하지 않아 노출이 과소 계산된다.

## 2. 일반적으로 만족해야 하는 성질

값의 표현이 정확하다. 넘침은 감지된다. 반올림 방향은 문서화되고 안전한 쪽이다. 직렬화가 왕복에서 값을 보존한다.

## 3. 제약

Hyperliquid perp의 가격은 유효숫자 5자리 이하이고 소수 자릿수는 `6 − szDecimals` 이하다. 수량은 `szDecimals` 자리다([조사 G](../research/hyperliquid-protocol.md)).
거래소 와이어 값은 문자열이며 뒤따르는 0을 제거해야 서명 해시가 맞는다.

## 4. 필수 조건과 선택 조건

필수: 정수 연산, 넘침 검사, 왕복 보존. 선택: 종목별 최적 스케일.

## 5. 대안

| 대안 | 설명 |
|---|---|
| A. `f64` | 가장 단순 |
| B. 십진 라이브러리(`rust_decimal`) | 96비트 십진수 |
| C. `i64` 고정 스케일 1e-8 newtype | 직접 작성. 곱셈만 `i128` 경유 |
| D. 종목별 tick·lot 정수 | 종목마다 스케일이 다르다 |

## 6. 비교

| 기준 | A | B | C | D |
|---|---|---|---|---|
| 정확성 | 아님 | 정확 | 소수 8자리까지 정확 | 정확 |
| 넘침 | 무한대·NaN | 검사 가능 | `checked_*`로 강제 | 검사 필요 |
| 의존성 | 없음 | 외부 crate | 없음 | 없음 |
| 종목 간 합산 실수 | — | — | 타입이 같아 가능. 종목별 장부로 분리해 막는다 | 스케일 혼동 위험 |
| 범위 | — | 넓다 | ±9.2e10 단위 | 종목에 따라 다르다 |

이 표의 값은 모두 정성 판단이거나 형식의 정의에서 나오는 사실이다. 측정값은 없다.

## 7. 선택과 이유

C. `crates/oms-core/src/num.rs`.

- 타입: `Qty`(수량, 음수 불가), `Px`(가격, 음수 불가), `Amount`(부호 있는 금액), `SQty`(부호 있는 포지션). 모두 `i64`, 단위 1e-8.
- 범위: 약 ±922억 단위. 금액으로 922억 USD, 가격으로 922억. 대상 상품에서 충분하다.
- 덧셈·뺄셈은 `checked_add`/`checked_sub`. 넘치면 요청은 `Overflow`로 거절되고, 이벤트 적용 중이면 `CoreFault`로 프로세스가 멈춘다.
  release 빌드에서도 `overflow-checks = true`다.
- `가격 × 수량`은 `i128`로 계산한다. 한도 비교용은 올림(`notional_ceil`): 노출을 과소 계산하지 않는다. 보고용 합계는 반올림(`notional_round`).
- 직렬화는 정규 십진 문자열이다(`"0.001"`, 지수 없음, 뒤 0 없음). 저널·스냅샷·API 모두 같다. JSON 숫자는 거부한다.
- 파싱은 소수 8자리 초과, 지수, `+`, 쉼표를 거부한다. 반올림해서 받아 주지 않는다.
- 시각은 `u64` 마이크로초다. 나노초면 2^53을 넘어 브라우저가 정확히 읽지 못한다.
- 거래소의 tick·lot·유효숫자 규칙은 종목 설정으로 검사한다(`qty_step`, `px_tick`, `px_max_sig_figs`). 정수 가격은 유효숫자 제한에서 예외다.

## 8. 포기한 장점, 남은 위험, 가정

- 소수 8자리를 넘는 종목은 표현할 수 없다. Hyperliquid perp는 6자리 이하다.
- 체결 금액 합계(`traded_notional`)는 체결마다 1e-8로 반올림한 값의 합이다. 보고용이며 한도 판단에 쓰지 않는다.
- 통화가 하나라는 가정이다. 여러 통화의 금액을 같은 타입으로 더하는 실수를 타입이 막지 못한다.

## 9. 근거

- `parses_business_examples`, `rejects_instead_of_rounding`, `formats_canonically`: 손으로 쓴 기대값.
- `notional_ceil_is_the_least_upper_bound`: 나눗셈 없이 `i128` 비교로 "결과 × 1e8 ≥ 정확한 곱, 차이 < 1e8"을 확인하는 property test.
- `format_parse_roundtrip`: 모든 `i64`에 대해 왕복 보존.
- `significant_figure_rule_exempts_integers`: 문서의 예(`123456`은 유효, `12345.6`은 무효).

## 10. 재검토 조건

소수 8자리를 넘는 상품, 여러 결제 통화, 계약 승수가 있는 상품을 다룰 때.
